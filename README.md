# OIMD-NaI: simulation and data behind "Optical-input model dependence in Geant4 light-collection corrections: a NaI(Tl) case study"

The Geant4 application, optical models, digitised inputs, run records,
literature records and analysis scripts behind the paper of that title
(Y. S. Karakaş and Ö. Beysi, submitted to *Nuclear Instruments and Methods in
Physics Research A*). Every number the paper quotes is read from the verdict
file `runs_scratch/gates_final.json`, which the scripts here regenerate from
the run records in `runs/`.

## What the study does

A measured scintillator light yield is corrected for light collection with a
Geant4 optical simulation. The study asks how far that correction depends on
which published optical model the simulation was fed, for a 3"×3" NaI(Tl)
crystal, varying one input at a time; digitises the published transmittance
curve that constrains the dominant term; scans the arrangement (geometry,
coupling, surface finish, reflector reflectance); surveys what published
light-yield measurements state about their own conditions; and documents two
reproducibility hazards in Geant4 11.4's optical physics found on the way.

## Layout

```
scint/        Python package: optical models, material tables, run registry, runner
sim/          Geant4 application (C++), built inside the container
scripts/      derivations, campaign driver, analysis, digitisers, literature survey
materials/    Geant4 material tables (GENERATED by scripts/make_material_variants.py)
data/         sourced inputs: digitised curves, literature records, provenance ledger
runs/         run records of the published campaign (see "Run records")
runs_scratch/ the verdict (gates_final.json) and the evidence files it rests on
containers/   Dockerfile pinning Geant4 11.4.2, and the equivalence tests
tests/        pytest suite
```

## Reproducing the results

Requirements: Docker; Python 3.12; poppler (`pdftoppm`, `pdfimages`) for the
digitisers.

```bash
# Python environment
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
pip install -e . --config-settings editable_mode=compat

# The pinned toolkit: Geant4 11.4.2 built from source (about an hour)
docker build -t scint:11.4.2 -f containers/Dockerfile .
docker run --rm -v "$PWD":/work -w /work scint:11.4.2 \
    bash -c 'cmake -S sim -B build/container && cmake --build build/container -j8'

# The campaign the paper reports: 60 runs of 2000 events, inside the container
sh scripts/run_in_container.sh --set all --events 2000 --jobs 2

# From run records to the verdict every quoted number is read from
python3 scripts/analyse_gates.py --json runs_scratch/gates_final.json
python3 -m pytest -q
```

`scripts/run_in_container.sh` refuses to run from an uncommitted tree or on a
pre-release toolkit, so that the commit and the toolkit tag each run records
are the ones that produced it. Runs are identified by the SHA-256 of their
configuration; a configuration that has already run is not run again, and a
run whose material file has changed since it was made is retired
automatically. `analyse_gates.py` admits only runs whose configuration the
runner currently defines and whose recorded material checksum matches the
file on disk.

### Inputs derived from published figures

Two curves are digitised from published figures whose PDFs are not
redistributed here (both are copyrighted); each digitiser records the SHA-256
of the file it read, calibrates the axes on the figure's own marks and reports
the residuals, and the committed CSVs are byte-identical to what the scripts
produce:

```bash
python3 scripts/digitise_mao_fig2.py --pdf <Mao, Zhang & Zhu, IEEE TNS 55 (2008) 2425>
python3 scripts/digitise_brown_corrigendum.py --pdf <Brown, Appl. Radiat. Isot. 194 (2023) 110721>
```

`scripts/derive_nai_abslength.py` is the analytic inversion of the stated
cut-off wavelength that the digitised curve replaced; the study keeps it as a
check.

### Literature survey

`scripts/collect_literature.py` runs the arXiv queries (recorded with their
dates and every identifier returned), `scripts/scan_reporting.py` and
`scripts/scan_yields.py` the keyword scans, `scripts/analyse_literature.py`
the statistics the paper quotes, and `scripts/scan_optical_practice.py` the
classification of optical inputs. The hand-extracted records are
`data/literature/ly_records.csv`; the provenance of every optical input is
`data/literature/optical_provenance.csv`.

## Run records

Every run directory holds `config.yaml` (the complete input), `env.json`
(git commit and dirty flag, Geant4 tag and pre-release flag, container image
identifier, dataset versions, seed), `status.json` (state, elapsed time,
binary and material-file checksums, output checksum, label aliases),
`run.mac` and the per-event output `output_nt_events.csv`. The Geant4 log
of each run is not tracked, for size, with one exception: the three attempts
at an unwrapped crystal under the look-up-table surface model (labels
`G4_wrap_none`, `G4_wrap_none_short`, `G4_wrap_none_tiny`; state `killed`)
are kept with their logs and their empty output files, because together they
are the record that no event completed (each log stops inside the
initialisation printout, at the last flushed block of the killed process's
output, not at the hang itself). The
reasons recorded when they were stopped give the explanation entertained at
the time; the cause found afterwards is in `sim/src/SurfaceCatalogue.cc`.

`runs_scratch/gates_final.json` is the verdict the paper is built from:
its header names the commit of the analysis, the schema, the toolkit tag and
the event count; its `runs` list carries every run it used with the checksums
above. `runs_scratch/gates_schema4_cascade.json` is the discarded campaign
that exposed the scintillation cascade, kept as its evidence.

The commit identifiers recorded in the run records and in the verdict header
are those of the development repository this history was derived from.
`RUN_COMMIT_MAP.tsv` maps each recorded identifier to the corresponding
commit here; the file trees are identical.

## Beyond this study

`scint/materials.py`, `scint/cost.py` and `data/elements/` implement the
stoichiometric, cost and critical-raw-material layer of a wider scintillator
screening framework that this study is the first part of. They are tested
here but not used by the paper.
